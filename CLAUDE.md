# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Private, invite-only book-challenge platform (French UI, code in English). Teams earn points by reading (per page), filling bingo grids and completing quests; each team also plays a shared branching "you're the hero" story voted on Discord/in-app with game effects. Full spec and phasing: `~/.claude/plans/we-will-start-from-drifting-dijkstra.md`.

Do not use the `dsi:*` skills/agents here (personal project, not a Davidson internal repo).

## Toolchain

- Node ≥ 22 — the system default `node` is v12. Use `export PATH=$HOME/.nvm/versions/node/v22.23.2/bin:$PATH` (or `nvm use`, see `.nvmrc`) before any npm command.
- npm (no pnpm on this machine).
- Secrets live in `.env.local` (gitignored; `DATABASE_URL` etc. come from `npx vercel env pull`, which also refreshes them). `prisma.config.ts` loads `.env.local` then `.env`. Vercel project is linked (`.vercel/`), Neon Postgres provisioned via the Vercel marketplace.

## Stack notes (Next.js 16 — conventions differ from older training data)

- Read `node_modules/next/dist/docs/01-app/02-guides/upgrading/version-16.md` before touching framework-level code. Key points already applied:
  - `proxy.ts` replaces `middleware.ts` (Node runtime only). It does an optimistic cookie check only.
  - `params`, `searchParams`, `cookies()`, `headers()` are Promises — always `await`.
  - Global helper types `PageProps<'/route'>`, `LayoutProps<'/route'>`, `RouteContext<'/route'>` (generated by `next typegen`/`next dev`).
  - Use `after()` from `next/server` for fire-and-forget side effects (Discord posts).
  - Cache Components (`cacheComponents`) are NOT enabled; pages are dynamic by default when they read the session.
- Prisma 7: config in `prisma.config.ts` (loads `.env` via dotenv), client uses the Neon driver adapter (`lib/db.ts`). No `url` in `schema.prisma`.
- Auth.js v5 (`auth.ts`): Discord-only OAuth, JWT sessions. Sign-in is refused unless an unused `Invite` matches the Discord id (or the user already exists); `events.createUser` consumes the invite (sets `discordId`, `role`, team membership).

## Architecture rules

- **Authorization lives in `lib/dal.ts`** (`requireUser`, `requireAdmin`, `getCurrentPlayer`), called inside every page, Server Action and Route Handler. Never rely on layouts or the proxy for security.
- **Scores are an append-only ledger** (`PointEvent`). Never store a mutable team total; team score = sum of `amount` within the challenge window. Multipliers (`Modifier`) are resolved when the event is written (`baseAmount`, `multiplier`, `amount` all stored). Undo = negative event.
- Pure game logic (points, bingo lines, vote resolution, story effects) goes in `lib/scoring/*` and `lib/story/*` with no I/O, and is unit-tested. Server Actions and Discord slash commands must call the same service functions (`lib/services/*`) — no duplicated business logic.
- Mobile-first UI (Tailwind 4), French copy with proper typography (apostrophes, accents).
